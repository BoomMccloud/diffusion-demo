### 2. Verify and stage the exact protocol-v2 artifacts

This cell only copies verified files to local NVMe. It does not load a model or
send a generation request.

```python
import hashlib
import json
import os
from pathlib import Path
import shutil

repo = Path(os.environ["BENCH_REPO"])
cache = Path("/content/drive/MyDrive/diffusiongemma-demo/diffusion-runner/v4_sm_80_nvcc_12_8_src_daca8075d871_harness_v2")
metadata = json.loads((cache / "build-info.json").read_text())
assert metadata["build_format_version"] == 4
assert metadata["protocol"] == 2
assert metadata["source_commit"] == "daca8075d871483545dd85d58ce11970b304b541"
assert metadata["runner_cache_key"] == cache.name

def sha256(path):
    digest = hashlib.sha256()
    with path.open("rb") as source:
        for chunk in iter(lambda: source.read(1024**2), b""):
            digest.update(chunk)
    return digest.hexdigest()

for name in ("llama-diffusion-cli", "softcap-backend-probe"):
    source = cache / name
    expected = metadata["artifacts"][name]
    assert source.stat().st_size == expected["bytes"], name
    assert sha256(source) == expected["sha256"], name
    target = Path("/content") / name
    shutil.copy2(source, target)
    target.chmod(0o755)

tokenizer_source = cache / "dependency-tokenizer"
if not tokenizer_source.is_file():
    tokenizer_source = repo / "archive/artifact-bundles/bench/results/dependency-density/2026-09-07/evidence/dependency-tokenizer"
assert sha256(tokenizer_source) == "4f79ab7b2fe1a1b495e69c343092c03d9c155dc579076e05a0c4bfaf28a76c1a"
tokenizer_target = Path("/content/dependency-tokenizer")
shutil.copy2(tokenizer_source, tokenizer_target)
tokenizer_target.chmod(0o755)

RUNNER_LOCAL_PATH = "/content/llama-diffusion-cli"
TOKENIZER_LOCAL_PATH = "/content/dependency-tokenizer"
print("protocol-v2 runner, backend probe, and tokenizer staged")
```

If the v4 cache is absent or any assertion fails, stop. Follow the pinned build
and native-test instructions in `bench/README.md`; save a new cache only after
the build manifest and hashes are complete. Never fall back to the format-v3
Cell 2 build.

## Prepare gate

Run the `business_benchmark.py prepare` command in `bench/README.md`. This is the
next repository action. It hashes the actual artifacts, tokenizes all 36 frozen
fixtures with both model files, verifies context fit, and sends no generation
request.

Continue only when the final JSON includes both:

```json
{"status":"launch_ready","generation_rpc_calls":0}
```

A refusal is a successful safety outcome. Keep its `reason` and `detail`, correct
the staged state, and rerun `prepare` against the same output directory only
when the registration rules in `bench/README.md` allow it. Do not launch on a
warning, an unavailable GPU identity, a mismatched artifact, or unsafe context.

## Diffusion run

After `prepare` returns the exact launch-ready gate, run the documented
`run-diffusion` command. A completed screen requires both the command's final
JSON and durable `summary.json` to report 36 attempts, `"status":"completed"`,
and `"stop_reason":"all_cases_completed"`.

Incorrect answers are benchmark observations and do not stop the batch. Runtime
errors, missing or ambiguous native stops, failed warmup, and insufficient time
produce an incomplete nonzero result that must be inspected before resuming.

## Resume, inspect, and stop

- Resume by rerunning `run-diffusion` with the same output directory,
  registration, worker configuration, and artifact paths. Completed request IDs
  are skipped and never silently replayed.
- Inspect `/content/business-worker-v1.log`, the case-level `*.result.json`
  files, `results.jsonl`, and `summary.json` before retrying a runtime failure.
- Do not create a fresh output directory merely to bypass an identity or resume
  refusal. Preserve the original evidence and resolve the stated mismatch.
- Treat the loaded worker and populated caches as expensive state. Before
  stopping or closing the accelerator, ask whether it should remain available
  for follow-up probes. Closing it can require remounting Drive, restaging large
  models, and reloading or rebuilding the native runner.

## Where development resumes

Use this decision order:

1. If real `prepare` has not returned launch ready, the next work is A100 staging
   and preparation.
2. If preparation passed but the diffusion summary is incomplete, inspect and
   safely resume the same registered run.
3. If the diffusion summary completed, preserve and review its 36 terminal rows.
4. Then implement the paired business AR runner. The matching Gemma autoregressive business phase is not implemented. It must reuse the same
   frozen fixtures, execution-order contract, scoring, provenance, and timing
   fields rather than the older synthetic dependency-density cases.
5. Analyze the paired screen only after both systems have complete evidence. Do
   not start a larger confirmation set until the screen identifies a useful and
   valid separation.
